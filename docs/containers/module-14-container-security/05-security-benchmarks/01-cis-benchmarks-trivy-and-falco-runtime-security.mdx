# Chapter 1 — Security Benchmarks: CIS, Trivy & Falco eBPF

> **Goal:** Master the compliance standards, static vulnerability gates, and real-time behavioral threat detection engines of **Enterprise Container Security** — implementing the **Center for Internet Security (CIS) Benchmarks** using `kube-bench` and `docker-bench-security`, automating **Static Image Scanning with Trivy**, and deploying **eBPF-Powered Kernel Runtime Threat Detection with Falco**.
>
> By the end of this chapter, you will understand:
> 1. How CIS Benchmarks standardize host, daemon, and container security hardening
> 2. How static vulnerability scanners parse OS package databases and application lockfiles
> 3. Why static scanning fails to detect in-memory zero-day attacks and malicious runtime behavior
> 4. How Falco captures raw Linux kernel system calls using eBPF probes in real time
> 5. How to write custom declarative Falco rules for detecting shells, shadow file reads, and reverse shells
> 6. How to establish a complete Shift-Left to Runtime defense pipeline across CI/CD and production

## Real-Life Analogy

Think of Enterprise Container Security as **the multi-tiered security system at an international commercial airport**:

- **1. Static Vulnerability Scanning / Trivy (The X-Ray Luggage Scanner):**
  - Before passengers board the aircraft (**Build & Deploy Time**), their luggage passes through an X-ray scanner (**Trivy scans the image layers**).
  - If a bomb or weapon is detected (**Known Critical CVE in OpenSSL or Log4j**), the suitcase is confiscated immediately (**CI pipeline fails build**).
- **2. CIS Benchmarks (The Airport Safety Building Code):**
  - Ensures the airport has working fire extinguishers, reinforced steel doors, and proper emergency exit signs (**Hardened Kubelet, Docker daemon, and host kernel configs**).
- **3. Runtime Threat Detection / Falco (The Plainclothes Air Marshal on the Flight):**
  - What if a passenger smuggles a plastic weapon that didn't show up on X-rays (**An unknown zero-day exploit**)?
  - The Air Marshal sits in the cabin watching passenger behavior (**Falco eBPF kernel probe**).
  - The moment a passenger stands up, pulls a knife, and demands to enter the cockpit (**Spawns `/bin/sh` or reads `/etc/shadow`**), the Air Marshal tackles them immediately (**Generates high-priority SIEM alert and isolates the pod**)!

## Real-Time Behavioral Security: Falco eBPF Rules

Falco operates at the kernel level using **eBPF (Extended Berkeley Packet Filter)** to intercept system calls and detect anomalous behavior with zero performance impact:

### Example: Detecting Reverse Shells in Production
```yaml
- rule: Terminal Shell Spawned in Container
  desc: A shell was spawned by an untrusted process inside a production container
  condition: >
    spawned_process and 
    container and 
    proc.name in (bash, sh, zsh, ksh, ash) and
    not proc.pname in (entrypoint.sh, docker-entrypoint)
  output: >
    SECURITY ALERT: Shell spawned inside container (user=%user.name 
    container_id=%container.id container_name=%container.name 
    proc=%proc.name cmdline=%proc.cmdline)
  priority: WARNING
  tags: [container, mitre_execution]
```

## Common Interview Questions

**Q1: What are the CIS Benchmarks, and why are they considered the baseline for container security?**

The **CIS (Center for Internet Security) Benchmarks** are globally recognized, consensus-based security configuration guides. The CIS Docker and Kubernetes Benchmarks define hundreds of prescriptive rules covering: (1) Host OS configuration; (2) Container daemon security settings (TLS, logging, cgroups); (3) Container image construction (non-root users, content trust); (4) Runtime restrictions (seccomp, dropped capabilities, no privileged flags). They provide an objective baseline used by compliance frameworks (SOC 2, PCI-DSS, ISO 27001, HIPAA).

**Q2: Why is static vulnerability scanning (with Trivy/Grype) insufficient on its own?**

Static scanners analyze **known package versions against vulnerability databases (NVD)** at build time:
1. **Zero-Day Blindness**: They cannot detect undisclosed zero-day vulnerabilities with no CVE yet.
2. **Behavioral Blindness**: They cannot detect runtime anomalies such as stolen credentials, reverse interactive shells spawned via web application bugs, in-memory cryptominers, or host file tampering.
3. **Configuration Drift**: They do not monitor if a developer runs a container with `--privileged` or mounts `/var/run/docker.sock`. 
Comprehensive security requires **Runtime Behavioral Threat Detection (Falco)** to protect active workloads.

**Q3: How does Falco use eBPF to monitor container runtime activity?**

Falco attaches **eBPF (Extended Berkeley Packet Filter) tracepoints** directly into the Linux kernel's system call entry and exit points (e.g. `sys_enter_execve`, `sys_enter_openat`, `sys_enter_connect`). When any process inside any container issues a syscall, the eBPF probe captures the event details (process name, PID, container ID, namespace, file path, IP address) and sends it to user space where the Falco engine evaluates it against user-defined YAML rules in **microseconds with near-zero CPU overhead**.

**Q4: How do you configure a CI/CD pipeline gate using Trivy?**

In your CI pipeline (GitHub Actions, GitLab CI, Jenkins), execute Trivy with explicit severity and exit code flags:
```bash
trivy image --exit-code 1 --severity CRITICAL my-app:${CI_COMMIT_SHA}
```
If Trivy finds any **CRITICAL** vulnerabilities, it returns exit code `1`, immediately terminating the CI pipeline and preventing the vulnerable image from being pushed to the container registry or deployed to production.

**Q5: What is the purpose of tools like `kube-bench` in Kubernetes clusters?**

`kube-bench` is an automated open-source Go tool (by Aqua Security) that checks whether a Kubernetes cluster is deployed in accordance with the security recommendations in the **CIS Kubernetes Benchmark**. It runs as a Kubernetes `Job` or daemon, inspects master and worker node configuration files (`/etc/kubernetes/manifests/`, `/var/lib/kubelet/config.yaml`), verifies file permissions, validates API server flags, and generates a comprehensive PASS/FAIL compliance report with remediation steps.
