# 📖 Kubernetes Master Definitions & Glossary

> **Deep Learning Guide (University-Level + Interview-Oriented)**

Welcome to the **Master Definitions & Glossary** for the entire Kubernetes Internals & Architecture Documentation Suite. This page compiles the formal, textbook-level definitions of core Kubernetes concepts across all 10 modules into a single, searchable reference.

---

## 🏛️ Module 1 — Kubernetes Core Architecture

> [!NOTE]
> 📖 **Formal Definition — Kubernetes Control Plane**
> The **Kubernetes Control Plane** is the central management layer of a Kubernetes cluster that maintains the cluster state, processes API requests, makes global scheduling decisions, and detects and responds to cluster events via its core components (`kube-apiserver`, `etcd`, `kube-scheduler`, `kube-controller-manager`).

> [!NOTE]
> 📖 **Formal Definition — API Server (`kube-apiserver`)**
> The **API Server** (`kube-apiserver`) is the primary front-end management component of the Kubernetes control plane that exposes the RESTful Kubernetes API, handles authentication, authorization, and admission validation, and serves as the sole gateway to the cluster's state storage (`etcd`).

> [!NOTE]
> 📖 **Formal Definition — etcd**
> **etcd** is a strongly consistent, distributed key-value store implementing the RAFT consensus algorithm that serves as the single source of truth and state database for all Kubernetes cluster configuration and live resource data.

> [!NOTE]
> 📖 **Formal Definition — Kubernetes Scheduler (`kube-scheduler`)**
> The **Kubernetes Scheduler** (`kube-scheduler`) is a control plane component that evaluates newly created or unscheduled Pods through a multi-phase plugin framework (Filtering, Scoring, Reserve, Permit, Bind) to select the optimal worker node for Pod execution based on resource availability and constraints.

> [!NOTE]
> 📖 **Formal Definition — Controller Manager (`kube-controller-manager`)**
> The **Controller Manager** (`kube-controller-manager`) is a control plane daemon that embeds core control loops (such as Deployment, ReplicaSet, Node, and Job controllers) that continuously read actual cluster state from the API Server and drive it toward the desired state declared in manifests.

> [!NOTE]
> 📖 **Formal Definition — kubelet**
> The **kubelet** is the primary node-level agent running on every Kubernetes worker node that communicates with `kube-apiserver` to register the node, execute Pod specifications (`PodSpecs`), interact with container runtimes via CRI, and monitor container health.

> [!NOTE]
> 📖 **Formal Definition — Container Runtime Interface (CRI)**
> The **Container Runtime Interface (CRI)** is a gRPC plugin interface that allows `kubelet` to communicate transparently with various container runtimes (such as `containerd` or `CRI-O`) without recompiling the Kubernetes codebase.

## 🌐 Module 2 — Networking

> [!NOTE]
> 📖 **Formal Definition — Kubernetes Networking Model**
> The **Kubernetes Networking Model** is an IP-per-Pod flat network specification requiring that all Pods can communicate with all other Pods across nodes without Network Address Translation (NAT), and all Nodes can communicate with all Pods without NAT, establishing a unified L3 virtual network plane across the cluster.

> [!NOTE]
> 📖 **Formal Definition — Container Network Interface (CNI)**
> The **Container Network Interface (CNI)** is a Cloud Native Computing Foundation (CNCF) specification and library that defines a standardized interface for network plugins to allocate IP addresses and configure network interfaces when containers are created and destroyed.

> [!NOTE]
> 📖 **Formal Definition — eBPF (Extended Berkeley Packet Filter)**
> **eBPF** is a revolutionary Linux kernel technology that allows sandboxed programs to run inside the Linux kernel without changing kernel source code or loading kernel modules, enabling high-performance packet routing, observability, and security filtering at near-wire speeds.

## 📦 Module 3 — Workloads & Scheduling

> [!NOTE]
> 📖 **Formal Definition — Pod**
> A **Pod** is the basic deployable execution unit in Kubernetes representing a single instance of a running process in the cluster, consisting of one or more co-located containers that share Linux network (`netns`), IPC, and UTS namespaces as well as persistent volume storage.

> [!NOTE]
> 📖 **Formal Definition — Deployment**
> A **Deployment** is a declarative workload resource that manages the rolling updates, rollbacks, scaling, and lifecycle of identical, stateless Pod replicas via underlying `ReplicaSet` resources.

> [!NOTE]
> 📖 **Formal Definition — StatefulSet**
> A **StatefulSet** is a workload controller designed for stateful applications that provides unique, persistent network identifiers (ordinal indices), persistent storage volume claims (`volumeClaimTemplates`), and ordered deployment and scaling guarantees.

## 💾 Module 4 — Storage

> [!NOTE]
> 📖 **Formal Definition — Kubernetes Volume**
> A **Kubernetes Volume** is an abstracted directory accessible to containers within a Pod, whose underlying storage medium (RAM disk, local SSD, network block device, or cloud storage object) and lifecycle are determined by the specified Volume plugin type.

> [!NOTE]
> 📖 **Formal Definition — Container Storage Interface (CSI)**
> The **Container Storage Interface (CSI)** is an industry-standard gRPC specification that enables storage vendors to develop out-of-tree plugins for volume provisioning, mounting, snapshots, and resizing without modifying Kubernetes core code.

## 🔒 Module 5 — Security

> [!NOTE]
> 📖 **Formal Definition — Kubernetes Authentication**
> **Kubernetes Authentication** is the initial security validation phase wherein `kube-apiserver` inspects credentials (such as X.509 client certificates, OIDC Bearer tokens, or webhook tokens) attached to an incoming API request to establish the verified identity (`Username`, `UID`, and `Groups`) of the requesting subject.

> [!NOTE]
> 📖 **Formal Definition — Role-Based Access Control (RBAC)**
> **Role-Based Access Control (RBAC)** is an authorization mechanism in Kubernetes that regulates access to cluster resources by assigning permission rules (verbs, API groups, resources) to subjects (Users, Groups, ServiceAccounts) via `RoleBindings` and `ClusterRoleBindings`.

---

## 📊 Module 6 — Observability

> [!NOTE]
> 📖 **Formal Definition — Metrics Server & Metrics API**
> **Metrics Server** is a cluster-wide aggregator of resource usage data that collects CPU and memory metrics from cAdvisor on each node and exposes them via the Kubernetes **Metrics API** (`metrics.k8s.io`) for consumption by `kubectl top` and autoscaling controllers (HPA/VPA).

> [!NOTE]
> 📖 **Formal Definition — PromQL (Prometheus Query Language)**
> **PromQL** is a functional query language used to evaluate and aggregate time-series metric data stored in Prometheus TSDB in real time.

---

## 🛡️ Module 7 — Reliability & Production Operations

> [!NOTE]
> 📖 **Formal Definition — Control Plane High Availability (HA)**
> **Control Plane High Availability (HA)** is a fault-tolerant deployment topology where core Kubernetes master components (`kube-apiserver`, `etcd`, `kube-scheduler`, `kube-controller-manager`) are replicated across multiple physical failure domains (availability zones/nodes) to guarantee API availability and state consistency during hardware failures.

> [!NOTE]
> 📖 **Formal Definition — Karpenter**
> **Karpenter** is an open-source just-in-time node provisioning controller that monitors unschedulable Pod requirements and directly provisions optimally-sized compute nodes without relying on node group abstractions.

---

## 🚀 Module 8 — CI/CD & GitOps

> [!NOTE]
> 📖 **Formal Definition — GitOps**
> **GitOps** is a cloud-native operational pattern where the entire target system's desired state is declared as version-controlled code in a Git repository, and an automated software agent continuously reconciles live cluster state to match the Git source of truth.

> [!NOTE]
> 📖 **Formal Definition — Argo CD**
> **Argo CD** is a declarative, GitOps continuous delivery tool for Kubernetes that monitors Git repositories and automatically synchronizes application states to target Kubernetes clusters.

---

## 🌐 Module 9 — Multi-Cluster & Fleet Management

> [!NOTE]
> 📖 **Formal Definition — Multi-Cluster Architecture**
> A **Multi-Cluster Architecture** is an enterprise infrastructure design pattern that deploys and orchestrates multiple independent Kubernetes clusters across regions, clouds, or edge locations to provide hard tenant isolation, disaster recovery, regulatory compliance, and reduced blast radius.

> [!NOTE]
> 📖 **Formal Definition — Cluster API (CAPI)**
> **Cluster API (CAPI)** is a CNCF subproject that uses Kubernetes-style declarative APIs and operators to automate cluster creation, configuration, upgrading, and lifecycle management across cloud infrastructure providers.

## 🤖 Module 10 — AI/ML Workloads, GPUs & Cloud-Native Innovations

> [!NOTE]
> 📖 **Formal Definition — Dynamic Resource Allocation (DRA)**
> **Dynamic Resource Allocation (DRA)** is an API framework introduced in Kubernetes 1.26 and stabilized in 1.30+ that allows third-party drivers to expose and manage specialized hardware devices (such as GPUs, FPGAs, DPUs, and RDMA NICs) using structured parameters and claim objects rather than simple scalar integer counters (`nvidia.com/gpu: 1`).

> [!NOTE]
> 📖 **Formal Definition — NVIDIA GPU Operator**
> The **NVIDIA GPU Operator** is a Kubernetes Operator built on the Operator framework that automates the management, provisioning, and lifecycle of all software components required to run GPU-accelerated workloads on Kubernetes (including host kernel drivers, container runtime hooks, device plugins, and telemetry exporters).

> [!NOTE]
> 📖 **Formal Definition — KubeRay Operator**
> **KubeRay** is an open-source Kubernetes Operator that automates the deployment, lifecycle management, and autoscaling of distributed Ray compute clusters on Kubernetes, orchestrating Ray Head and Worker node pods using declarative custom resource definitions (`RayCluster`, `RayJob`, `RayService`).

> [!NOTE]
> 📖 **Formal Definition — Kueue**
> **Kueue** is a CNCF incubator job queuing controller for Kubernetes that manages how and when batch jobs (such as PyTorchJobs, RayJobs, or standard Jobs) are admitted into the cluster, controlling resource quota allocation, multi-tenant priority queuing, and fair-share borrowing across teams.

> [!NOTE]
> 📖 **Formal Definition — vLLM & PagedAttention**
> **vLLM** is an open-source high-throughput LLM serving engine that implements **PagedAttention**, an algorithm inspired by operating system virtual memory paging that manages Key-Value (KV) cache in non-contiguous physical GPU VRAM blocks to eliminate memory fragmentation and maximize request batching parallelism.

> [!NOTE]
> 📖 **Formal Definition — Vector Database**
> A **Vector Database** is a specialized database system optimized to store, index, and query high-dimensional mathematical vector embeddings (generated by AI models) using Approximate Nearest Neighbor (ANN) search algorithms (such as HNSW or IVF-Flat) with sub-10ms query latencies.

> [!NOTE]
> 📖 **Formal Definition — WebAssembly (Wasm) & runwasi**
> **WebAssembly (Wasm)** is a portable, memory-safe, binary instruction format designed for sandboxed execution. In Kubernetes, **`runwasi`** is a containerd shim v2 plugin that enables container runtimes to execute Wasm bytecode modules directly inside lightweight Wasm virtual machines (such as Wasmtime or Spin) with sub-millisecond cold start times without full OCI container overhead.

> [!NOTE]
> 📖 **Formal Definition — Confidential Containers (CoCo)**
> **Confidential Containers (CoCo)** is an open-source CNCF project that leverages hardware Trusted Execution Environments (TEEs—such as AMD SEV-SNP, Intel TDX, or AWS Nitro Enclaves) and microVM hypervisors to cryptographically isolate in-memory container execution and data-in-use from untrusted host operating systems, cloud admins, and co-located workloads.
