> **Goal:** Master secure, version-controlled secret management in GitOps using **Mozilla SOPS (Secrets OPerationS)** and Cloud **Key Management Services (KMS)** — understanding why Base64 encoding is not encryption, dissecting the two-tier **Envelope Encryption** architecture (AES-256 Data Encryption Keys wrapped by Cloud KMS), mastering **Value-Only Encryption** to maintain clean Git diffs and code review readability, configuring declarative **`.sops.yaml`** rules, and integrating automated in-cluster decryption into **Flux CD v2** and **Argo CD**.

## Real-Life Analogy

Think of Mozilla SOPS as **a high-security transparent envelope with opaque carbon-paper privacy windows stored inside a bank vault**:

- **The Base64 Delusion (The Glass Envelope):** Storing a standard Kubernetes `Secret` (`data: password: cGFzc3dvcmQxMjM=`) in a Git repository is like putting cash in a clear glass envelope and leaving it on the street. Base64 is **encoding**, not encryption—anyone who looks at it can read your database password in 0.1 seconds.
- **Full File Encryption (The Locked Solid Steel Box - PGP/GPG):** If you encrypt the entire file into unreadable binary blobs (`secret.gpg`), nobody can read your secrets, but you completely break GitOps! When a developer opens a Pull Request to update a password, Git shows: *"1,000 lines deleted, 1,000 lines added (Binary Diff)."* Reviewers cannot see what changed, merge conflicts cannot be resolved, and accidents happen.
- **The Mozilla SOPS Magic (The Value-Only Carbon Envelope):** SOPS encrypts **only the values** while leaving the YAML keys, comments, and structure in pure plaintext:
  - `database_host: postgres-prod.internal` (Plaintext - Reviewers can read this!)
  - `database_password: ENC[AES256_GCM,data:x9fK2...,iv:...]` (Encrypted - 100% Secure!)
- **The Two-Tier Key (Envelope Encryption):** SOPS encrypts your password with a fast random local key (**Data Encryption Key - DEK**), and then locks that key inside a cloud bank vault (**AWS KMS / GCP KMS Key Encryption Key - KEK**).

## Configuring `.sops.yaml` Directory Rules

Place `.sops.yaml` in the root of your Git repository to automate KMS key selection by path:

```yaml
# .sops.yaml in GitOps Repository Root
creation_rules:
  # 1. Production Secrets encrypted with Production AWS KMS Key
  - path_regex: environments/production/.*\.enc\.yaml$
    kms: "arn:aws:kms:us-east-1:123456789012:key/a1b2c3d4-5678-90ab-cdef-111122223333"
    encrypted_regex: "^(data|stringData)$" # Encrypts ONLY data and stringData keys!

  # 2. Staging Secrets encrypted with Staging KMS Key
  - path_regex: environments/staging/.*\.enc\.yaml$
    kms: "arn:aws:kms:us-east-1:123456789012:key/b2c3d4e5-6789-01bc-def0-444455556666"
    encrypted_regex: "^(data|stringData)$"

  # 3. Local Development Secrets encrypted with Age Key
  - path_regex: environments/dev/.*\.enc\.yaml$
    age: "age1ql3z7hjy54pw3hyww5ayyfg7zqgvc7w3j2elw8zmrj2kg5sfn9aqmcac8p"
```

## Native Decryption in Flux CD v2

Flux natively supports Mozilla SOPS decryption inside `Kustomization` objects:

```yaml
apiVersion: kustomize.toolkit.fluxcd.io/v1
kind: Kustomization
metadata:
  name: payment-production-secrets
  namespace: flux-system
spec:
  interval: 5m
  path: ./environments/production
  prune: true
  sourceRef:
    kind: GitRepository
    name: gitops-manifests
  # Native SOPS Decryption Provider!
  decryption:
    provider: sops
    secretRef:
      name: sops-age-key               # Required if using Age / PGP; omitted for AWS KMS IRSA!
```

## Working with SOPS on the Command Line

```bash
# 1. Encrypt a raw secret file in place
sops -e -i environments/production/payment-secret.enc.yaml

# 2. Open an encrypted file in an interactive text editor (Decrypts in RAM, re-encrypts on save!)
sops environments/production/payment-secret.enc.yaml

# 3. Decrypt and inspect the plaintext output locally
sops -d environments/production/payment-secret.enc.yaml
```

## Common Interview Questions

**Q1: What is Mozilla SOPS, and why is "Value-Only Encryption" critical for GitOps?**

Mozilla SOPS is an open-source security tool that provides file-level encryption for structured configuration formats (YAML, JSON, ENV). Traditional encryption tools (like GPG or OpenSSL) encrypt the entire file into an opaque binary blob, which destroys GitOps workflows by preventing Pull Request diff reviews and breaking automated merge conflict resolution. SOPS performs **Value-Only Encryption**: it encrypts the sensitive data values while keeping the YAML keys, metadata, and structure in human-readable plaintext, allowing engineers to review schema changes in Git while keeping secrets cryptographically secure.

**Q2: How does the Envelope Encryption model work in Mozilla SOPS?**

SOPS uses a two-tier Envelope Encryption architecture:
1. When encrypting a file, SOPS generates a random 256-bit symmetric **Data Encryption Key (DEK)** locally.
2. The DEK encrypts the secret values using the `AES-256-GCM` cipher.
3. SOPS sends the DEK to an external **Key Management Service (KMS)** (such as AWS KMS, GCP KMS, or Azure Key Vault). The KMS wraps the DEK with its master **Key Encryption Key (KEK)**.
4. The encrypted DEK is embedded directly in the file's `sops.kms` metadata block. When decrypting, SOPS sends the wrapped DEK back to KMS for unwrapping.

**Q3: How does Flux CD v2 decrypt SOPS-encrypted secrets without storing private keys in Git?**

Flux's `kustomize-controller` has built-in support for SOPS. When using cloud KMS (e.g. AWS KMS): (1) The `kustomize-controller` pod is attached to an AWS IAM Role via IAM Roles for Service Accounts (IRSA); (2) When Flux encounters a `.enc.yaml` file containing a `sops` metadata block, it uses its in-cluster IAM credentials to make an authenticated `kms:Decrypt` API call; (3) It decrypts the values purely in memory and applies the unencrypted `Secret` directly to the Kubernetes API server, with zero secrets stored on disk.

**Q4: What is the purpose of the `encrypted_regex` configuration in `.sops.yaml`?**

By default, SOPS encrypts all scalar values in a YAML file. Setting `encrypted_regex: "^(data|stringData)$"` restricts encryption **strictly to the `data` and `stringData` fields** of Kubernetes Secret manifests. Non-sensitive metadata (such as `metadata.name`, `metadata.namespace`, `apiVersion`, and `kind`) remains completely unencrypted, allowing Kubernetes admission webhooks and GitOps controllers to parse resource types without decrypting the entire file.

**Q5: What are the security advantages of using `age` encryption keys with SOPS for local development?**

`age` is a modern, lightweight, simple file encryption tool designed as a modern replacement for complex PGP/GPG toolchains. It uses standard `X25519` curve public keys and `ChaCha20-Poly1305` ciphers. Unlike PGP, which requires managing complex keyrings and subkeys, `age` keys are simple, portable single-line strings, making them ideal for containerized CI pipelines and local developer secrets.
