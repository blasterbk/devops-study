## Root Cause 1: Resolving IPSec MTU Blackholes via TCP MSS Clamping

When small `ping` (ICMP) packets succeed between clusters but large `curl` / `HTTP` downloads hang indefinitely, **you have an MTU Blackhole**.

### Resolution: Enforce TCP MSS Clamping in Submariner Gateway:
```bash
# 1. Inspect the local Gateway interface MTU
ip link show submariner-ipx

# 2. Inject TCP Maximum Segment Size (MSS) Clamping rule in iptables:
iptables -t mangle -A FORWARD -p tcp --tcp-flags SYN,RST SYN -j TCPMSS --clamp-mss-to-pmtu

# 3. Or manually set interface MTU to 1400 to account for IPSec encryption overhead:
ip link set dev submariner-ipx mtu 1400
```

## Root Cause 2: Diagnosing Globalnet NAT Translation Failures

If packets cross the tunnel but the destination pod never replies, inspect the Submariner `iptables` NAT translation chains on the Gateway Node:

```bash
# 1. Inspect Submariner Egress SNAT rules
iptables -t nat -L SUBMARINER-POSTROUTING -n -v

# 2. Inspect Submariner Ingress DNAT rules (Translates Globalnet IP to Pod IP)
iptables -t nat -L SUBMARINER-PREROUTING -n -v

# Look for packet counter increments:
# Chain SUBMARINER-PREROUTING (1 references)
# pkts bytes target     prot opt in     out     source        destination
#   42  2520 DNAT       all  --  *      *       0.0.0.0/0     242.20.1.15  to:10.244.1.15
```

## Root Cause 3: Resolving Edge Fleet GitOps Stalls

When an edge cluster reconnects after a prolonged outage and its `BundleDeployment` is stuck in `Status: Modified` or `Status: Error`:

```bash
# 1. Query failed or drifting BundleDeployments on the edge cluster
kubectl get bundledeployments.fleet.cattle.io -A -o json | jq '.items[] | select(.status.ready==false) | {name: .metadata.name, nonReady: .status.nonReadyStatus}'

# 2. Force an immediate bundle re-evaluation on the edge cluster
kubectl annotate bundledeployment <name> -n fleet-default fleet.cattle.io/force-sync="$(date +%s)" --overwrite

# 3. Restart the edge fleet-agent to clear in-memory synchronization locks
kubectl rollout restart deployment fleet-agent -n cattle-fleet-system
```

## Common Interview Questions

**Q1: What is an "MTU Blackhole" in multi-cluster networking, and why does it cause HTTP connections to hang?**

An MTU Blackhole occurs when network traffic is encapsulated inside tunnel headers (such as IPSec ESP or VXLAN), which adds **56 to 72 bytes of overhead** to each packet. If a client transmits a standard 1500-byte packet with the `DF` (Don't Fragment) bit set, the encapsulated packet exceeds the 1500-byte Maximum Transmission Unit (MTU) of the underlying cloud network or public internet. Intermediate routers silently drop the oversized packet without returning an ICMP "Fragmentation Needed" message. As a result, small TCP handshakes succeed, but large HTTP data payloads hang indefinitely.

**Q2: How does TCP MSS Clamping solve the MTU Blackhole problem?**

**TCP Maximum Segment Size (MSS) Clamping** intercepts the initial TCP handshake (`SYN` / `SYN-ACK` packets) passing through the gateway. It rewrites the advertised MSS value in the TCP header to a smaller number (e.g. `1400 bytes`). This forces both the client and server to limit their application data payloads to 1400 bytes, ensuring that even after adding IPSec encapsulation headers, the final packet remains well under the 1500-byte internet MTU limit, preventing packet drops.

**Q3: Which firewall ports must be opened between clusters for Submariner IPSec tunnels to establish?**

For Submariner IPSec connectivity across public clouds or the internet:
1. **UDP Port 4500 (IPSec NAT-Traversal / NAT-T)**: Mandatory for encrypted ESP payload transit through cloud NATs.
2. **UDP Port 500 (IKE - Internet Key Exchange)**: Used for initial cryptographic key negotiation.
3. **UDP Port 4827**: Used by Submariner's tunnel health check probes to monitor end-to-end latency and packet loss.

**Q4: How do you troubleshoot a Globalnet NAT mapping failure where a remote service is unreachable?**

1. Run `subctl show endpoints` to verify that the remote service has been allocated a valid Globalnet IP from its assigned global CIDR pool.
2. On the local Gateway Node, inspect `iptables -t nat -L SUBMARINER-POSTROUTING` to verify that outbound packets have their source IP translated (SNAT).
3. On the remote Gateway Node, inspect `iptables -t nat -L SUBMARINER-PREROUTING` to verify that incoming global IPs are translated (DNAT) to the real target in-cluster Pod IP.

**Q5: How do you resolve a GitOps deployment stall when an edge cluster suffers out-of-band manual configuration drift?**

When someone manually modifies a live resource on an edge cluster (`kubectl edit`), the GitOps controller (Fleet or Argo CD) flags the deployment as `Drifted / Modified`. In strict edge environments:
1. If **Self-Healing** is enabled, the agent automatically overwrites manual edits with the Git baseline.
2. If the agent is stuck in an error state due to schema locks, apply the annotation `fleet.cattle.io/force-sync` to force a complete cache re-sync, or execute `kubectl rollout restart deployment fleet-agent` to reset local reconciliation buffers.
