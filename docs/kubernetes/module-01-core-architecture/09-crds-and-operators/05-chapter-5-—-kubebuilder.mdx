# Module 1.9 — CRDs & Operators

# Chapter 5 — Kubebuilder

> **Goal:** Learn how **Kubebuilder** is used to build production-grade Kubernetes Operators. By the end of this chapter, you'll understand how Kubebuilder scaffolds APIs, Controllers, Webhooks, RBAC, CRDs, and how it leverages the `controller-runtime` library to simplify Operator development.
>
> By the end of this chapter, you will understand:
>
> ```text
> 1. Kubebuilder project layout: api/, controllers/, config/, Makefile
> 2. Generating Go API types: Spec, Status, and deepcopy generators
> 3. Controller scaffolding: Reconciler interface, SetupWithManager, and Builder pattern
> 4. Marker comments (`// +kubebuilder:...`): generating CRDs, RBAC, and validation
> 5. Manager components: Cache, Client, Scheme, Webhooks, Leader Election
> 6. Admission webhooks in Kubebuilder: Mutating and Validating Webhook setup
> 7. Local integration testing with `envtest` and real etcd/API Server binaries
> 8. Packaging and deploying with Kustomize manifests and Docker containers
> ```

# Real-Life Analogy

Think of Kubebuilder like an advanced architectural CAD application with automated 3D printing tools.

```text
Architectural CAD Analogy:

Instead of hand-drafting thousands of structural blueprints (raw client-go code)
Architect selects building parameters (Go structs in `api/v1/`)
CAD tool generates certified structural blueprints (CRDs, RBAC, Webhooks in `config/`)
CAD generates the mechanical wiring framework (Manager, Cache, Informers)
Engineer only writes the custom mechanical logic (the `Reconcile()` function)
When parameters change, engineer clicks "Recompile" (`make manifests`) to update all blueprints
```

| Architectural CAD Tool | Kubebuilder Framework |
| :--- | :--- |
| Structural parameter definitions | Go structs (`_types.go`) |
| CAD annotations & markers | `// +kubebuilder:subresource:status`, `// +kubebuilder:rbac:...` |
| Automated blueprint generator | `controller-gen` (generates CRD & RBAC YAML) |
| Mechanical wiring framework | `controller-runtime` Manager & Builder |
| Custom engineering logic | `Reconcile(ctx, req)` method |
| Integration simulation chamber | `envtest` test suite |

> **Important:** Kubebuilder relies on **code generation driven by Go marker comments** (`// +kubebuilder:...`). Whenever you modify Go structs or RBAC annotations, you **must run `make manifests` and `make generate`** to regenerate the CRD YAML, deepcopy methods, and RBAC ClusterRoles. Never manually edit the YAML files inside `config/crd/bases` or `config/rbac` — manual edits will be overwritten on the next build!

# What is Kubebuilder?

Kubebuilder is an official Kubernetes framework for building Operators.

It is developed and maintained by the Kubernetes SIG API Machinery community.

Kubebuilder provides:

- Project scaffolding
- API generation
- Controller scaffolding
- CRD generation
- RBAC generation
- Webhook scaffolding
- Testing framework
- Deployment manifests

---

# Kubebuilder Architecture

```text
                Kubebuilder CLI
  |
  v
            Generates Project Structure
  |
  v
            Uses controller-runtime
  |
  v
                Builds Operator
```

Kubebuilder itself is **not** a runtime library.

It is a project generation tool.

# What is controller-runtime?

`controller-runtime` is the Go framework used by most modern Operators.

It provides:

- Manager
- Client
- Cache
- Informers
- Controller Builder
- Webhooks
- Leader Election
- Metrics
- Health Probes

Almost every production Operator uses this library.

Examples:

- cert-manager
- Crossplane
- Prometheus Operator
- External Secrets Operator
- KEDA

# Manager

The Manager is the central runtime component.

It starts and coordinates:

- Controllers
- Cache
- Informers
- Webhooks
- Metrics Server
- Health Checks
- Leader Election

Think of it as the runtime container for the Operator.

---

# Manager Architecture

```text
Manager

+--────── Controllers

+--────── Cache

+--────── Client

+--────── Scheme

+--────── Webhooks

+--────── Metrics

+--────── Leader Election
```

Controllers do not create these components individually.

They receive them from the Manager.

# Scheme

Example:


# Production Best Practices

✔ Keep business logic inside `Reconcile()`.

✔ Never edit generated files unless necessary.

✔ Organize APIs by version.

✔ Use validation markers instead of manual validation.

✔ Read from the Cache whenever possible.

✔ Keep Controllers focused on one responsibility.

✔ Write EnvTest-based integration tests.

✔ Regenerate manifests whenever API types change.

# Common Misconceptions

### ❌ Misconception 1

Kubebuilder runs Operators.

**Correct:** Kubebuilder generates the project. The runtime is provided by `controller-runtime`.

---

### ❌ Misconception 2

Kubebuilder replaces Kubernetes.

**Correct:** It builds Operators that run on Kubernetes.

---

### ❌ Misconception 3

Developers must manually write CRD YAML.

**Correct:** Kubebuilder generates CRDs from Go types.

---

### ❌ Misconception 4

Developers must manually write DeepCopy functions.

**Correct:** They are automatically generated.

---

### ❌ Misconception 5

The Client always queries the API Server.

**Correct:** Reads generally use the shared Cache, while writes go to the API Server.

---

### ❌ Misconception 6

The Manager is optional.

**Correct:** In controller-runtime, the Manager coordinates shared components such as Cache, Client, Controllers, and Webhooks.

---

### ❌ Misconception 7

Kubebuilder and Operator SDK are competing runtime frameworks.

**Correct:** Both commonly use `controller-runtime`; Kubebuilder focuses on scaffolding, while Operator SDK adds additional tooling and packaging capabilities.

# Common Interview Questions

### Q1. What is Kubebuilder?

An official Kubernetes framework for scaffolding and building production-grade Operators.

---

### Q2. What is controller-runtime?

A Go library that provides the runtime components needed to build Kubernetes Controllers and Operators.

---

### Q3. What is the role of the Manager?

It initializes and manages shared components such as Controllers, Cache, Client, Webhooks, Metrics, and Leader Election.

---

### Q4. Why is the Scheme required?

It maps Kubernetes API objects to Go types for serialization and deserialization.

---

### Q5. Why does controller-runtime use a Cache?

To reduce API Server load by serving most read operations from locally synchronized objects.

---

### Q6. What is the Builder Pattern?

A fluent API used to configure Watches, owned resources, and controller behavior.

---

### Q7. What types of Webhooks can Kubebuilder generate?

Mutating, Validating, and Conversion Webhooks.

---

### Q8. How does Kubebuilder generate CRDs?

It uses Go type definitions and markers, then `controller-gen` produces the CRD YAML.

---

### Q9. What is EnvTest?

A lightweight testing environment that runs an API Server and etcd for realistic controller tests.

---

### Q10. Why use Kubebuilder instead of writing an Operator manually?

It eliminates repetitive boilerplate, follows Kubernetes best practices, and integrates seamlessly with controller-runtime.

# Troubleshooting Guide

| Problem | Likely Cause |
|----------|--------------|
| CRD not generated | API types or generation markers missing |
| Controller never starts | Not registered with the Manager |
| Unknown resource type | Scheme registration missing |
| Controller cannot watch resources | RBAC permissions incomplete |
| Reads return stale data | Cache not synchronized yet |
| Webhook not invoked | Webhook configuration or certificates incorrect |
| Reconciliation never triggered | Builder watches not configured properly |
| Tests fail in EnvTest | CRDs not installed or test environment not initialized |
