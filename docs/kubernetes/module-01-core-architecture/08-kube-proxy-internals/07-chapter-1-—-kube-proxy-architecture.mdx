# Technology Comparison

| Feature | iptables | IPVS | eBPF |
|----------|----------|------|-------|
| Kernel-Based | Yes | Yes | Yes |
| Packet Processing | Rule Matching | Table Lookup | Programmable Datapath |
| Service Lookup | Rule Chains | Hash Tables | BPF Maps |
| Scheduling Algorithms | Basic | Multiple | Implementation Specific |
| Large Cluster Performance | Good | Better | Excellent |
| Rule Synchronization | Heavy | Moderate | Minimal |
| Programmability | Low | Medium | Very High |
| Observability | Limited | Moderate | Excellent |
| kube-proxy Required | Yes | Yes | Optional |
| Learning Difficulty | Low | Medium | High |

# Decision Matrix

| Cluster Size / Requirement | Recommended Dataplane |
|----------------------------|-----------------------|
| Small Development Cluster | iptables |
| Medium Production Cluster | iptables or IPVS |
| Large Enterprise Cluster | IPVS or eBPF |
| Very Large Cloud Platform | eBPF |
| Advanced Observability | eBPF (e.g., Cilium) |
| Legacy Compatibility | iptables |

> **Note:** The best choice depends on kernel support, operational expertise, managed Kubernetes platform capabilities, and organizational requirements—not just cluster size.

# Common Production Problems

| Problem | Root Cause | Solution |
|----------|------------|----------|
| Service unreachable | Missing endpoints | Verify Service selector and EndpointSlices |
| No backend traffic | Readiness probe failure | Fix application readiness |
| Random TCP failures | conntrack exhaustion | Increase capacity and tune timeouts |
| High latency | Large iptables rule sets | Consider IPVS or eBPF |
| Uneven traffic | Long-lived connections or affinity | Review load-balancing behavior |
| Client IP lost | ExternalTrafficPolicy configuration or SNAT | Review traffic policy |
| Pod receives no traffic | Endpoint not Ready | Check readiness and EndpointSlice status |
| kube-proxy issues | Watch synchronization or configuration | Inspect kube-proxy logs and Node state |

# Common Misconceptions

### ❌ "A Service owns Pods."

**Correct:** A Service selects Pods using labels.

---

### ❌ "ClusterIP exists on a network interface."

**Correct:** It is a virtual IP implemented by the dataplane.

---

### ❌ "kube-proxy forwards packets."

**Correct:** kube-proxy programs the Linux networking dataplane.

---

### ❌ "Every packet is load balanced."

**Correct:** New connections are load balanced. Existing connections reuse state.

---

### ❌ "conntrack is part of Kubernetes."

**Correct:** conntrack is a Linux kernel subsystem.

---

### ❌ "IPVS completely replaces iptables."

**Correct:** Kubernetes IPVS mode still uses some iptables rules for integration.

---

### ❌ "eBPF is only for networking."

**Correct:** eBPF is a general-purpose kernel execution technology with networking being one of many applications.
