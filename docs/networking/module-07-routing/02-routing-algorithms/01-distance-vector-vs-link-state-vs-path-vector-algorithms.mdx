## Real-Life Analogy

Think of the 3 routing algorithm families as **three different ways motorists find directions through a city**:

- **Distance Vector ("Asking Strangers at Gas Stations"):**
  - You stop at a gas station: *"Which way to Downtown?"* The attendant says: *"Turn right, it's about 5 miles"*. You don't know what the road looks like beyond that, you just trust their rumor (**Routing by rumor**).
- **Link State ("Using a Live Satellite GPS Map"):**
  - Your in-car GPS downloads a complete, perfect blueprint of every road, bridge, and speed limit in the entire state (**Link State Database / LSDB**). Your computer runs Dijkstra's algorithm locally to calculate the absolute fastest route.
- **Path Vector ("International Flight Itinerary Tracker"):**
  - Instead of measuring miles, your ticket lists every country you must cross: `[USA -> UK -> Germany -> Japan]`. If you see `USA` in the list twice, you instantly detect a circular loop and abort (**AS-Path Loop Prevention**).

### 2. Distance Vector Loop Mitigations

- **Count-to-Infinity:** When a link fails, Router A and Router B bounce increments to each other until reaching maximum metric ($16 = \infty$).
- **Split Horizon:** A router never advertises a route back out the same interface through which it originally learned it.
- **Poison Reverse:** When a link fails, the router explicitly advertises the route with an infinite metric ($16$) to immediately purge neighbor caches.
- **Hold-Down Timers:** Prevents a router from accepting new routing updates for a recently dropped route for a period (e.g. 180s), allowing network-wide stabilization.

## Common Interview Questions

**Q1: How does Dijkstra's Shortest Path First (SPF) algorithm guarantee a loop-free topology?**

In Link State protocols (OSPF), every router floods Link State Advertisements (LSAs) so that every node possesses an identical, complete mathematical graph (Link State Database) of all routers and links. Each router places itself at the root of a Shortest Path Tree (SPT) and computes the minimum-cost branch to every destination. Because a tree structure mathematically contains **zero cycles or closed loops**, loop-free forwarding is mathematically guaranteed.

**Q2: What is the primary scalability bottleneck of Distance Vector protocols?**

Distance Vector protocols periodically transmit their **entire routing table** to all immediate neighbors. As the network grows to hundreds of subnets, these periodic broadcasts consume massive link bandwidth and CPU. Furthermore, convergence times scale poorly ($O(N)$ hops), and the 15-hop limit in RIP prevents deployment in networks with a diameter $>15$ routers.

**Q3: How does Path Vector (BGP) detect and discard routing loops?**

Every BGP update message includes the **AS-Path attribute**, which lists every Autonomous System Number (ASN) the route has traversed (e.g., `AS-PATH: 64512 13335 15169`). When a BGP border router receives an update from an eBGP peer, it scans the AS-Path. If its **own ASN is found anywhere in the list**, the router immediately discards the route, permanently preventing inter-domain routing loops.

**Q4: What is the difference between OSPF (Link State) and IS-IS (Link State)?**

Both use Dijkstra's SPF algorithm. However:
- **OSPF:** Operates on top of the IPv4/IPv6 IP layer (IP Protocol 89).
- **IS-IS (Intermediate System to Intermediate System):** Operates directly on Layer 2 (Data Link layer) using ISO CLNS (Connectionless Network Service) encapsulation. This makes IS-IS independent of IP and highly popular in Tier-1 carrier optical backbones.

**Q5: What is Administrative Distance (AD) and when is it evaluated compared to Metric?**

- **Administrative Distance (AD):** Evaluates the trustworthiness between **different routing protocols** (e.g. Connected=0, Static=1, OSPF=110, RIP=120). The router selects the route with the lowest AD to insert into the RIB.
- **Metric:** Evaluates multiple competing paths learned from the **same routing protocol** (e.g., two OSPF paths with costs 10 vs 20).
