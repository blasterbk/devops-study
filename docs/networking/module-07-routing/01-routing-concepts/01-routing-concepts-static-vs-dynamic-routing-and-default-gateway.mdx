# Chapter 1 — Routing Concepts: Static vs Dynamic Routing, Routing Tables & Longest Prefix Match

> **Goal:** Master the operational mechanics of Layer 3 IP routing. Understand how routers inspect destination IP headers, evaluate the Routing Information Base (RIB) and Forwarding Information Base (FIB), execute the Longest Prefix Match (LPM) algorithm, forward packets across Default Gateways, and choose between Static and Dynamic routing architectures.
>
> By the end of this chapter, you will understand:
> 1. The structural anatomy of a Linux and enterprise router routing table
> 2. How the Longest Prefix Match (LPM) binary trie lookup algorithm works
> 3. Static routing: configuration, floating static backup routes, and administrative overhead
> 4. Dynamic routing: automated topology discovery, neighbor adjacencies, and convergence
> 5. Default Gateway mechanics (`0.0.0.0/0` default route) and next-hop Layer 2 ARP resolution
> 6. CLI routing inspection and manipulation with Linux `ip route` and `route`

## Real-Life Analogy

Think of IP routing as **navigating highway intersections on a cross-country road trip**:

- **Local Subnet (Your Neighborhood):**
  - If a destination is on your local street, you drive directly to their driveway (**Direct Layer 2 ARP delivery**).
- **The Routing Table (The Highway Signpost):**
  - Signpost A: *"All traffic heading to Chicago (`10.0.0.0/8`) take Exit 4"*.
  - Signpost B: *"All traffic heading to Downtown Chicago Financial District (`10.1.2.0/24`) take Express Exit 4B"*.
  - You follow **Signpost B** because it is more specific (**Longest Prefix Match**).
- **Default Gateway (`0.0.0.0/0` - The Universal On-Ramp):**
  - If a sign doesn't exist for your remote target, you follow the default sign: *"For all other destinations, take Interstate 80 East (**Default Gateway**)"*.

## Deep Technical Content

### 1. The Longest Prefix Match (LPM) Rule

When multiple routes in the routing table encompass a target destination IP, the router **always selects the route with the longest binary subnet prefix (highest prefix number)** because it represents the most specific network path.

```text
Target IP: 10.1.1.50
Route A:   10.0.0.0/8      (Matches first 8 bits:   00001010...)
Route B:   10.1.0.0/16     (Matches first 16 bits:  00001010.00000001...)
Route C:   10.1.1.0/24     (Matches first 24 bits:  00001010.00000001.00000001...)  <-- WINNER!
```

### 2. Static vs Dynamic Routing Comparison

```text
 ┌──────────────────────┬──────────────────────────────────────────┬──────────────────────────────────────────┐
 │ Feature              │ Static Routing                           │ Dynamic Routing (BGP, OSPF, IS-IS)       │
 │──────────────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
 │ **Route Learning**   │ Manually entered by administrator        │ Automated exchange between routers       │
 │ **CPU & Memory**     │ Zero CPU/RAM overhead                    │ Periodic Hello packets & SPF computation │
 │ **Link Failure**     │ Fails silently (traffic black-holed)     │ Automatic rerouting around failed links  │
 │ **Scalability**      │ Poor ($O(N^2)$ complex in large nets)    │ High (Scales to global Internet)         │
 │ **Security**         │ High (No routing advertisement spoofing) │ Requires cryptographic auth (MD5/SHA256) │
 └──────────────────────┴──────────────────────────────────────────┴──────────────────────────────────────────┘
```

## Hands-On Lab: Managing Linux Routing Tables

```bash
# Step 1: Inspect the kernel IPv4 routing table
ip route show

# Step 2: Query the exact route and interface the kernel selects for an IP (LPM test)
ip route get 8.8.8.8

# Step 3: Add a static network route via a specific next-hop gateway
sudo ip route add 10.50.0.0/16 via 192.168.1.1 dev eth0

# Step 4: Add a blackhole route to instantly drop malicious or unwanted traffic
sudo ip route add blackhole 198.51.100.0/24

# Step 5: Delete a static route
sudo ip route del 10.50.0.0/16 via 192.168.1.1
```

## Common Interview Questions

**Q1: What is the difference between the Routing Information Base (RIB) and Forwarding Information Base (FIB)?**

- **RIB (Control Plane):** The master routing database containing all routes learned from all dynamic protocols (OSPF, BGP) and static configurations, along with administrative distances and metrics.
- **FIB (Data Plane):** The optimized, hardware-accelerated lookup table programmed directly into router TCAM (Ternary Content-Addressable Memory) or kernel cache. It contains only the single best active path for each destination to forward packets at line rate.

**Q2: What is a Floating Static Route and how is it configured?**

A Floating Static Route is a backup static route configured with a higher **Administrative Distance (AD)** than the primary dynamic routing protocol (e.g. static AD set to 120 vs OSPF AD of 110). As long as OSPF is active, the static route remains dormant in the RIB. If OSPF fails, the router automatically activates the floating static route to maintain connectivity.

**Q3: How does a router determine whether a destination IP is local or remote?**

The sending host or router performs a **bitwise binary AND operation** between the destination IP and its own subnet mask. If the resulting Network ID matches the local interface's Network ID, the destination is on-link; the host sends a Layer 2 ARP Request. If the Network IDs differ, the destination is remote; the host encapsulates the packet in a frame addressed to the **Default Gateway's MAC address**.

**Q4: What is a Routing Loop and how do Layer 3 headers prevent infinite circulating packets?**

A routing loop occurs when misconfigured routing tables cause two or more routers to repeatedly bounce a packet back and forth to each other. The **IPv4 Time-To-Live (TTL)** and **IPv6 Hop Limit** fields prevent infinite circulation: every router decrements TTL by 1; when TTL reaches 0, the router discards the packet and sends an **ICMP Type 11 (Time Exceeded)** message to the sender.

**Q5: What is Policy-Based Routing (PBR) and how does it differ from destination routing?**

Standard routing forwards packets solely based on the **Destination IP**. **Policy-Based Routing (PBR)** allows network administrators to route packets based on custom matching criteria: Source IP, Protocol (TCP vs UDP), Source Port, or DSCP QoS tags (e.g., routing HTTP traffic out Fiber ISP 1 while routing backup traffic out Satellite ISP 2).
