# Chapter 2 — Kubernetes Services & CoreDNS: ClusterIP, NodePort, LoadBalancer & ndots:5

> **Goal:** Master the internal packet forwarding and discovery mechanisms of **Kubernetes Services** and **CoreDNS**. Understand how virtual `ClusterIP` addresses work (without pingable interfaces), `kube-proxy` iptables vs IPVS packet translation, `NodePort` and cloud `LoadBalancer` integration, `Headless Services`, high-scale `EndpointSlices`, and CoreDNS name resolution tuning (including the infamous `ndots:5` 5-query performance penalty).
>
> By the end of this chapter, you will understand:
> 1. What a `ClusterIP` actually is: a non-routable virtual IP residing purely in kernel `iptables` / IPVS tables
> 2. The 4 Service Types: `ClusterIP`, `NodePort` (ports 30000–32767), `LoadBalancer`, and `ExternalName`
> 3. `Endpoints` vs `EndpointSlice` controller architecture ($O(1)$ scaling vs $O(N)$ large cluster scaling)
> 4. Headless Services (`clusterIP: None`): direct DNS A/SRV records pointing to Pod IPs for StatefulSets
> 5. CoreDNS Architecture: `Corefile` plugin pipeline (`kubernetes`, `forward`, `cache`, `errors`)
> 6. The `ndots:5` search path expansion and optimizing DNS query latency in production

## Real-Life Analogy

Think of Kubernetes Services and CoreDNS as **a corporate receptionist and dynamic internal phone extension directory**:

- **Pods (Individual Temporary Employees):**
  - Pods are ephemeral; they crash, get rescheduled, and their phone extensions (**Pod IPs**) change constantly.
- **ClusterIP Service (The Department Main Phone Number):**
  - A permanent phone number: *"Customer Support: Ext #100"*. No physical desk has the label #100; when you dial #100, the automated PBX switch (**`kube-proxy` iptables / IPVS**) randomly rings one of the 5 active support agents (**Backend Pods**).
- **CoreDNS & `ndots:5` (The Over-Helpful Phone Operator):**
  - When you ask the operator for `"google.com"`, because `ndots:5` is set, the operator first checks:
    1. *"Is there a `google.com.default.svc.cluster.local`?"*
    2. *"Is there a `google.com.svc.cluster.local`?"*
    3. *"Is there a `google.com.cluster.local`?"*
    4. Finally checks the real public Internet (**5 DNS queries for every single external API call!**).

## Deep Technical Content

### 1. The CoreDNS `ndots:5` Bottleneck

Every Kubernetes Pod automatically receives `/etc/resolv.conf`:

```text
nameserver 10.96.0.10
search default.svc.cluster.local svc.cluster.local cluster.local c.my-project.internal
options ndots:5
```

- **How `ndots:5` works:** If a queried domain contains fewer than 5 dots (e.g. `api.stripe.com` has 2 dots), the resolver **appends every search domain first** before querying the root:
  1. `api.stripe.com.default.svc.cluster.local` $\to$ `NXDOMAIN`
  2. `api.stripe.com.svc.cluster.local` $\to$ `NXDOMAIN`
  3. `api.stripe.com.cluster.local` $\to$ `NXDOMAIN`
  4. `api.stripe.com.c.my-project.internal` $\to$ `NXDOMAIN`
  5. `api.stripe.com` $\to$ `203.0.113.5` (**Success on 5th attempt!**)
- **The Fix:** Append a trailing dot in application code (`api.stripe.com.`) or tune `ndots:2` in Pod `dnsConfig`.

---

### 2. Endpoints vs EndpointSlices

- **Legacy `Endpoints` Object:** A single Kubernetes API resource stored all backend pod IPs for a service. For a service with 5,000 pods, updating 1 pod caused the API server and etcd to transmit a **massive 2MB object** to all 500 nodes ($1\text{ GB of network churn}$).
- **Modern `EndpointSlice` (K8s 1.21+):** Splits endpoints into discrete slices of **100 endpoints each**, reducing control plane network churn by $95\%$.

## Common Interview Questions

**Q1: Why is a Kubernetes `ClusterIP` not pingable with the `ping` utility?**

A `ClusterIP` is a **virtual IP address that does not exist on any physical or virtual network interface card (NIC)**. It exists purely as an in-kernel `iptables` / IPVS / eBPF translation rule programmed by `kube-proxy`. Because `kube-proxy` only configures translation rules for specific **Layer 4 TCP and UDP ports** (e.g. port 80/443), sending an **ICMP Echo Request (ping)** hits no listening interface or translation rule and is silently dropped by the kernel.

**Q2: What is a Headless Service (`clusterIP: None`) and when is it required?**

A Headless Service is configured with `spec.clusterIP: None`. Kubernetes does not allocate a virtual ClusterIP, and `kube-proxy` creates zero load-balancing rules. Instead, CoreDNS returns **direct DNS `A` records for all healthy individual Pod IPs**. Headless services are strictly required for **StatefulSets (Kafka, MongoDB, Cassandra)** where microservices need to address specific stateful replica pods directly (e.g. `kafka-0.kafka-service.default.svc.cluster.local`).

**Q3: What is the difference between `kube-proxy` iptables mode and IPVS mode?**

- **iptables Mode:** Rules are evaluated sequentially ($O(N)$ linear complexity). Large clusters with thousands of services suffer high CPU usage and slow packet processing.
- **IPVS Mode (IP Virtual Server):** Operates using **in-kernel hash tables ($O(1)$ constant time complexity)**. Supports advanced scheduling algorithms (Least Connections, Weighted Round Robin, Locality-Based) and handles 100,000+ Services with negligible CPU overhead.

**Q4: How does `externalTrafficPolicy: Local` prevent extra network hops on `NodePort` services?**

- **`Cluster` (Default):** Every node accepts traffic on the NodePort and randomly forwards it to any pod in the cluster, potentially adding a second network hop across nodes and applying SNAT (losing real client IP).
- **`Local`:** The node **only routes traffic to Pods running locally on that exact node**. If no local pod exists, traffic is dropped. This eliminates the extra inter-node hop and **preserves the real client source IP**.

**Q5: How do you fix the CoreDNS `ndots:5` 5-query performance penalty for external API calls?**

1. **Fully Qualified Domain Names (FQDNs):** Append a trailing dot in application config: `https://api.stripe.com./v1/charges` (tells the resolver to skip the search list).
2. **Pod `dnsConfig`:** Configure `spec.dnsConfig.options: [{name: "ndots", value: "2"}]` on pods that make heavy outbound external internet calls.
3. **NodeLocal DNSCache:** Deploy `NodeLocal DNSCache` as a DaemonSet to cache DNS queries locally on each node's loopback interface (`169.254.20.10`).
