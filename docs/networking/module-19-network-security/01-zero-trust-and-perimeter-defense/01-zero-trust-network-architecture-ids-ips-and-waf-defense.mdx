# Chapter 1 — Zero Trust Architecture & Perimeter Defense: IDS, IPS, WAF & Microsegmentation

> **Goal:** Master the paradigm shift from legacy "Castle-and-Moat" perimeter security to modern **Zero Trust Network Architecture (ZTNA / NIST SP 800-207)** and Google BeyondCorp. Understand deep packet inspection systems: Intrusion Detection Systems (IDS) vs Intrusion Prevention Systems (IPS: Snort, Suricata, Zeek), Next-Generation Firewalls (NGFW), microsegmentation, and egress data loss prevention (DLP).
>
> By the end of this chapter, you will understand:
> 1. The fundamental failure of Castle-and-Moat security: assumed internal trust and lateral movement attack paths
> 2. The 3 Core Pillars of Zero Trust (NIST SP 800-207): **Verify Explicitly**, **Use Least Privilege Access**, and **Assume Breach**
> 3. Signature-based vs Anomaly-based intrusion detection: Snort and Suricata multi-threaded packet inspection
> 4. IDS (Passive / SPAN / TAP port monitoring) vs IPS (Inline active packet dropping)
> 5. Microsegmentation: isolating east-west traffic between workloads in the same VPC or subnet
> 6. CLI exploration and packet capture analysis with `suricata` and `tshark`

## Real-Life Analogy

Think of Zero Trust vs Castle-and-Moat security as **a medieval castle with a moat vs a modern high-security airport**:

- **Castle-and-Moat (Legacy Perimeter Security):**
  - A giant moat and armed guards at the main gate (**Perimeter Firewall**). If an enemy infiltrates the castle disguised as a chef (**Stolen VPN credentials**), they can wander freely into the royal treasury and bedrooms with zero internal checks (**Unrestricted Lateral Movement**).
- **Zero Trust (The Modern Airport):**
  - **Every single doorway requires authentication.**
  - You must scan your passport and boarding pass to enter the lobby, scan it again to enter security, scan it again at duty-free, and scan it a fourth time at the airplane gate.
  - Even if someone climbs the perimeter fence, they cannot open a single door inside the terminal without explicit biometric verification (**Assume Breach**).

## Deep Technical Content

### 1. IDS (Passive) vs IPS (Inline)

```text
 ┌──────────────────────┬──────────────────────────────────────────┬──────────────────────────────────────────┐
 │ Feature              │ Intrusion Detection System (IDS)         │ Intrusion Prevention System (IPS)        │
 │──────────────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
 │ **Placement**        │ **Out-of-Band (Passive SPAN / TAP Port)**│ **Inline (In-Band directly in datapath)**│
 │ **Action on Attack** │ Logs alert and sends syslog/webhook      │ **Actively drops malicious packets**     │
 │ **Network Impact**   │ Zero latency impact; zero false-pos drop │ Adds minor packet latency; false-pos risk│
 │ **Failure Mode**     │ Fails open (Traffic continues if crashes)│ Fails closed (Can cause complete outage) │
 │ **Examples**         │ Zeek (Bro), Snort (Passive mode)         │ Suricata (Inline NFQUEUE mode), Snort 3  │
 └──────────────────────┴──────────────────────────────────────────┴──────────────────────────────────────────┘
```

---

### 2. Snort / Suricata Rule Syntax Anatomy

```text
alert tcp $EXTERNAL_NET any -> $HOME_NET 80 (msg:"WEB-ATTACK SQL Injection attempt"; flow:to_server,established; content:"UNION SELECT"; nocase; sid:1000001; rev:1;)
```

- **Action:** `alert` (or `drop` in IPS mode).
- **Header:** Protocol (`tcp`), Source (`$EXTERNAL_NET any`), Destination (`$HOME_NET 80`).
- **Payload Inspection:** Looks for string `"UNION SELECT"` (case-insensitive) on active TCP streams.
- **Rule Metadata:** `sid` (Snort ID) and `rev` (Revision).

## Common Interview Questions

**Q1: What are the 3 core principles of Zero Trust defined by NIST SP 800-207?**

1. **Verify Explicitly:** Always authenticate and authorize based on all available data points (user identity, location, device health status, service workload identity, and data classification) rather than trusting network location.
2. **Use Least Privilege Access:** Limit user and service access with Just-In-Time (JIT) and Just-Enough-Access (JEA), Risk-Based Adaptive Polices, and data protection.
3. **Assume Breach:** Minimize blast radius by segmenting access by network, user, devices, and application awareness. Encrypt all end-to-end sessions (mTLS) and utilize analytics to gain visibility and threat detection.

**Q2: What is the difference between a Network TAP and a Switch SPAN Port for IDS packet capture?**

- **SPAN Port (Port Mirroring):** The physical network switch software copies frames to a mirror port. Under heavy 100% switch CPU load, the switch **drops mirrored SPAN packets first**, causing the IDS to miss real cyberattacks.
- **Network TAP (Test Access Point):** A passive, dedicated hardware splitter inserted directly into the physical fiber cable. It splits the optical light beam with **zero software processing and 100% guaranteed packet delivery** even during saturation.

**Q3: How does Microsegmentation prevent Ransomware from spreading across a datacenter?**

In a flat network, once a ransomware payload infects a single employee workstation or web server, it scans the local `/24` subnet using SMB (Port 445) and RDP (Port 3389) to infect all adjacent servers (**Lateral Movement**). **Microsegmentation** (via Kubernetes NetworkPolicies or hypervisor firewalls) blocks all peer-to-peer east-west communication between servers in the same subnet, trapping the ransomware inside the single infected node.

**Q4: What is the difference between Signature-Based Detection and Anomaly-Based Detection in IDS/IPS?**

- **Signature-Based (Snort/Suricata):** Compares packet bytes against a database of known exploit signatures (e.g. matching a specific Log4j string). Ultra-fast with near-zero false positives for known threats, but completely blind to brand-new **Zero-Day vulnerabilities**.
- **Anomaly-Based (Machine Learning / Behavioral):** Establishes a baseline of normal network traffic patterns (bandwidth, packet rates, protocols). Flags deviations (e.g., a web server suddenly opening outbound SSH connections to foreign IPs at 3 AM). Detects zero-days, but has higher false-positive rates.

**Q5: What is Google BeyondCorp and how did it eliminate corporate VPNs?**

Google BeyondCorp is the enterprise implementation of Zero Trust. Instead of connecting to an internal corporate network via a slow VPN, all internal corporate applications (bug trackers, HR tools, code repos) are exposed directly to the public internet through a secure **Identity-Aware Proxy (IAP)**. Access is granted based on verified user identity (SAML/OIDC + FIDO2 hardware MFA) and device state (enrolled, encrypted, updated OS), making the physical network location completely irrelevant.
