## Real-Life Analogy

Think of network devices as **the specialized personnel and facilities managing a global distribution warehouse**:

- **Hub (Layer 1 - Megaphone in a Common Hall):**
  - Whenever any worker speaks, a megaphone broadcasts their voice to every single person in the warehouse. If two workers speak at once, sound waves collide, causing incomprehensible gibberish (**Single collision domain, half-duplex**).
- **Layer 2 Switch (Layer 2 - Smart Pneumatic Tube Sorter):**
  - An intelligent sorting clerk reads the exact recipient name badge on the capsule, checks their internal directory (**CAM Table**), and sends the capsule directly to that specific recipient's desk tube without disturbing anyone else (**Isolated collision domains, full-duplex**).
- **Router (Layer 3 - International Customs & Shipping Depot):**
  - An international logistics coordinator who reads country and postal codes (**IP addresses**), determines the fastest highway or air-freight route, and ships freight across municipal and national borders (**Segments broadcast domains**).
- **Stateful Firewall (Layer 4/7 - Armed Security Checkpoint):**
  - Security guards who inspect every person entering and exiting. They maintain a visitor logbook (**State Table**); if you leave the building to fetch lunch, they automatically recognize and permit your return without re-screening (**Stateful connection tracking**).
- **Load Balancer (Layer 4/7 - Reception Hostess / Queue Manager):**
  - A front desk dispatcher who greets incoming customers and evenly distributes them across 10 available bank tellers to prevent any single teller from becoming overwhelmed (**Round-Robin / Least-Connections balancing**).

### 2. Collision Domains vs Broadcast Domains

Understanding domain boundaries is fundamental to network engineering:

```text
 ┌──────────────────────┬─────────────────────────────────────────────────┬───────────────────────────────────────────┐
 │ Property             │ Collision Domain                                │ Broadcast Domain                          │
 │──────────────────────┼─────────────────────────────────────────────────┼───────────────────────────────────────────┤
 │ **Definition**       │ Network segment where simultaneous packet       │ Network segment reached by a Layer 2      │
 │                      │ transmissions collide on shared physical media. │ broadcast frame (`ff:ff:ff:ff:ff:ff`).    │
 │ **Separated By**     │ Layer 2 Switches, Layer 3 Routers, Bridges      │ Layer 3 Routers, Layer 3 Switches, VLANs  │
 │ **Hub Behavior**     │ 1 Single Collision Domain across all ports      │ 1 Single Broadcast Domain                 │
 │ **Switch Behavior**  │ **Each individual port is its own isolated**    │ 1 Single Broadcast Domain across all      │
 │                      │ **Collision Domain** (Full-duplex, no collisions)│ ports (unless split by VLANs)             │
 │ **Router Behavior**  │ Each port is an isolated Collision Domain       │ **Each individual port is an isolated**   │
 │                      │                                                 │ **Broadcast Domain**                      │
 └──────────────────────┴─────────────────────────────────────────────────┴───────────────────────────────────────────┘
```

### 3. Layer 2 Switch: How CAM / MAC Learning Tables Work

When a switch boots, its Content Addressable Memory (CAM) table is completely empty. When Host A (`00:AA:AA:AA:AA:AA`) on Port 1 transmits a frame destined for Host B (`00:BB:BB:BB:BB:BB`) on Port 3:

```text
   Step 1 (Source Learning):
   The switch reads the Source MAC in the Ethernet header.
   CAM Table Entry: [Port 1 -> 00:AA:AA:AA:AA:AA | TTL: 300s]

   Step 2 (Forwarding Decision):
   The switch searches its CAM table for Destination MAC 00:BB:BB:BB:BB:BB.
   - If Found: The frame is forwarded ONLY out of Port 3 (Unicast Forwarding).
   - If NOT Found (Unknown Unicast): The switch FLOODS the frame out of ALL ports
     except Port 1.

   Step 3 (Target Reply):
   When Host B replies, the switch reads Host B's Source MAC from Port 3.
   CAM Table Entry: [Port 3 -> 00:BB:BB:BB:BB:BB | TTL: 300s]
   Future communication between Host A and Host B is now directly switched at hardware line rate.
```

## Hands-On Lab: Inspecting Linux Bridging, Forwarding Tables & ARP Cache

```bash
# Step 1: Create a virtual Linux bridge (simulates a physical Layer 2 Switch)
sudo ip link add name br0 type bridge
sudo ip link set dev br0 up

# Step 2: Create two virtual Ethernet pairs (veth cables) and plug them into the bridge
sudo ip link add veth1 type veth peer name c1-eth0
sudo ip link add veth2 type veth peer name c2-eth0

sudo ip link set dev veth1 master br0
sudo ip link set dev veth2 master br0

sudo ip link set dev veth1 up
sudo ip link set dev veth2 up

# Step 3: Inspect the bridge Forwarding Database (CAM / MAC Table in Linux)
bridge fdb show dev br0

# Step 4: View the operating system Layer 3 ARP cache
ip neigh show

# Step 5: Clean up virtual bridge and interfaces
sudo ip link del br0 2>/dev/null
sudo ip link del c1-eth0 2>/dev/null
sudo ip link del c2-eth0 2>/dev/null
echo "Virtual bridge lab cleaned successfully"
```

## Common Interview Questions

**Q1: What is the fundamental difference between a Layer 2 Switch and a Layer 3 Switch?**

A **Layer 2 Switch** operates strictly at the Data Link layer, forwarding frames based on 48-bit MAC addresses stored in its Content Addressable Memory (CAM) table. It cannot route traffic between different IP subnets or VLANs without an external router. A **Layer 3 Switch** combines high-density Layer 2 switching with hardware-accelerated Layer 3 routing using **Ternary Content Addressable Memory (TCAM)** ASICs. It can route IP packets between local VLANs at wire speed (billions of packets per second) with near-zero latency, offloading inter-VLAN routing from perimeter routers.

**Q2: What is the difference between a Packet Filtering Firewall and a Stateful Packet Inspection (SPI) Firewall?**

A **stateless packet filtering firewall** inspects each packet in complete isolation based on static access control lists (ACLs matching Source IP, Dest IP, Port). It cannot determine if a packet is part of an ongoing legitimate session, requiring administrators to open broad ranges of high ports for return traffic. A **Stateful Packet Inspection (SPI) firewall** maintains a dynamic state table tracking active TCP handshakes (SYN, SYN-ACK, ACK) and UDP pseudo-connections. When an internal host initiates an outbound request to an external server, the firewall automatically creates a temporary state table entry permitting return traffic exclusively for that active flow, blocking unsolicited external packets.

**Q3: How does a switch isolate collision domains while preserving a single broadcast domain?**

A switch provides dedicated, full-duplex transmission paths for every individual switch port. When two hosts transmit simultaneously on different ports, the switch buffers frames in port memory and routes them across its internal switching fabric directly to the destination ports without collision, making **each individual switch port its own isolated Collision Domain**. However, when a host transmits an Ethernet broadcast frame (`ff:ff:ff:ff:ff:ff` such as an ARP request), the switch is required by standard to flood that frame to all active ports on the VLAN, meaning the entire switch remains a **single Broadcast Domain**.

**Q4: When should you deploy a Layer 4 Load Balancer vs a Layer 7 Load Balancer?**

A **Layer 4 Load Balancer** (e.g., Linux IPVS, AWS NLB, Maglev) inspects only IP 5-tuples (Source/Dest IP and Port) at the transport layer without terminating the TCP or TLS connection. It offers ultra-high throughput (millions of requests per second), ultra-low latency, and minimal CPU overhead, making it ideal for ingress traffic distribution, gaming, and raw TCP/UDP streams. A **Layer 7 Load Balancer** (e.g., Envoy, NGINX, AWS ALB) terminates TCP and decrypts TLS, enabling content-based routing (HTTP URL paths, headers, cookies, gRPC methods), rate limiting, and microservice traffic splitting at the cost of higher CPU consumption.

**Q5: What is MAC Flooding and how do enterprise switches defend against it?**

**MAC Flooding** is a cyberattack where an attacker floods a Layer 2 switch with thousands of bogus source MAC addresses per second. This exhausts the finite memory capacity of the switch's CAM table. Once full, the switch can no longer learn legitimate MACs and defaults to **Fail-Open (Fail-Hub) mode**, flooding all incoming unicast frames to every port on the switch, allowing the attacker to sniff sensitive network traffic. Enterprise switches prevent this using **Port Security**, which limits the maximum number of learned MAC addresses per physical port (e.g., max 1 or 2) and automatically disables the port if a violation occurs.
