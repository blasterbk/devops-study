# Chapter 1 — OSPF Fundamentals: Backbone Area 0, LSA Types 1–7 & DR/BDR Elections

> **Goal:** Master Open Shortest Path First (OSPFv2 for IPv4, OSPFv3 for IPv6, RFC 2328 & RFC 5340). Understand two-tier hierarchical Area design (Backbone Area 0), Link State Advertisement (LSA) types 1 through 7, Designated Router (DR) and Backup Designated Router (BDR) election mechanics on multi-access networks, and the 8-stage OSPF neighbor state machine.

> 6. CLI exploration and diagnostic commands in FRR / Linux

## Real-Life Analogy

Think of OSPF area architecture as **a national parcel logistics distribution network**:

- **Backbone Area 0 (Interstate Superhighway Hub):**
  - The central high-speed transit hub connecting all states. Every state must directly connect to Area 0 (**No disconnected partitions**).
- **Non-Backbone Areas (State Postal Districts):**
  - Area 1 (California) and Area 2 (Texas) maintain complete internal street maps of their own territory.
- **Area Border Routers (ABR — Interstate Port of Entry):**
  - Instead of forcing Texas drivers to memorize every alleyway in California, the California ABR summarizes: *"California is reachable via Highway 10 (**Type 3 Summary LSA**)"*.
- **DR / BDR (Elected District Mail Dispatchers):**
  - In a room with 10 postmen, rather than each postman talking to all 9 others ($45\text{ conversations}$), they elect a **Head Dispatcher (DR)** and **Deputy (BDR)**. Everyone talks only to the DR/BDR, cutting chatter by 80%.

### 1. The 7 Primary LSA Types

```text
 ┌──────────┬──────────────────────┬────────────────────────┬──────────────────────────────────────────────────────────┐
 │ LSA Type │ Name                 │ Generated By           │ Flooding Boundary & Contents                             │
 │──────────┼──────────────────────┼────────────────────────┼──────────────────────────────────────────────────────────┤
 │ **Type 1**│ Router LSA          │ Every OSPF Router      │ Flooded within local Area only; lists local links & cost │
 │ **Type 2**│ Network LSA         │ Designated Router (DR) │ Flooded within multi-access broadcast segment (VLAN)     │
 │ **Type 3**│ Summary LSA (Network)│ Area Border Router (ABR)| Flooded between areas; summarizes inter-area prefixes   │

 │ **Type 5**│ AS-External LSA     │ ASBR Router            │ Flooded across entire OSPF domain; external routes       │
 │ **Type 7**│ NSSA External LSA   │ ASBR inside NSSA Area  │ Flooded within NSSA Area only; converted to Type 5 by ABR│
```

### 3. DR and BDR Election Mechanics

On broadcast networks (Ethernet), OSPF elects a **Designated Router (DR)** and **Backup Designated Router (BDR)** to prevent $N(N-1)/2$ full-mesh neighbor adjacencies:
1. **Highest OSPF Priority** wins (Default = `1`, Range `0–255`; Priority `0` means never eligible for DR).
2. **Tie-Breaker:** Highest **Router ID (RID)** (Highest Loopback IP, or highest physical IP).
3. Non-DR routers (**DROther**) establish full adjacency only with the DR and BDR (using multicast `224.0.0.6`). Adjacencies between two DROther routers remain in the **`2-Way` state**.

## Common Interview Questions

**Q1: Why must all non-backbone OSPF areas connect directly to Area 0?**

OSPF uses a **two-tier hub-and-spoke area hierarchy** to prevent inter-area routing loops. Because OSPF relies on Distance Vector logic between areas (Type 3 Summary LSAs do not contain full topology details), allowing traffic to flow directly between non-backbone areas (e.g. Area 1 $\to$ Area 2 $\to$ Area 3) would create inter-area routing loops. Forcing all inter-area traffic through Area 0 acts as a universal loop-prevention boundary.

**Q2: What is an OSPF Virtual Link and when is it deployed?**

An OSPF Virtual Link is a logical tunnel through a non-backbone area used when a non-backbone area (e.g. Area 2) cannot physically connect directly to Area 0 (for instance, following a corporate merger). A virtual link is built between the Area 2 ABR and a Backbone ABR across an intermediate transit area (e.g. Area 1), logically patching Area 2 into Area 0.

**Q3: What are the requirements for two OSPF routers to form an adjacency?**

To transition from `Init` to `2-Way` and `Full` state, two OSPF neighbors must match on:
1. **Area ID** and **Area Type** (Stub/NSSA flags)
2. **Subnet Mask** on the connecting link
3. **Hello and Dead Timers** (Default: 10s Hello, 40s Dead)
4. **Authentication password / cryptographic hash**
5. **MTU size** (Mismatch causes session to hang in `ExStart` / `Exchange` state)
6. **Unique Router IDs** (Duplicate RIDs drop adjacency)

**Q4: What is the difference between a Stub Area and a Totally Stubby Area?**

- **Stub Area (Cisco/Standard):** Blocks Type 5 External LSAs. Routers inside the stub area can reach other internal OSPF areas (via Type 3 summary LSAs) and use an injected default route (`0.0.0.0/0`) for external traffic.
- **Totally Stubby Area (Cisco proprietary extension):** Blocks **both Type 5 External LSAs AND Type 3 Summary LSAs**. The ABR injects a single Type 3 default route for all inter-area and external traffic, reducing LSDB memory footprint to the absolute minimum.

**Q5: Why do OSPF neighbors get stuck in the `ExStart` or `Exchange` state?**

The most common cause of an OSPF session stuck in `ExStart` or `Exchange` is an **MTU Mismatch** between the two connecting router interfaces. During ExStart, routers negotiate master/slave status and exchange Database Description (DBD) packets. If Router A has MTU 1500 and Router B has MTU 1450, Router B drops the oversized DBD packet from Router A, causing the handshake to stall indefinitely.
