## Deep Technical Content

### 1. The Reference Bandwidth Bottleneck

Because OSPF was standardized when 100 Mbps FastEthernet was state-of-the-art, the default Reference Bandwidth is **100 Mbps ($10^8$ bps)**. Because cost is an integer:
- 100 Mbps Cost = 1
- 1 Gbps Cost = 1
- 10 Gbps Cost = 1
- 100 Gbps Cost = 1

**Without tuning, OSPF treats a 100 Mbps copper link and a 100 Gbps fiber link as identical cost!**
Production best practice:

```text
router ospf 1
  auto-cost reference-bandwidth 1000000   ! Sets 1 Tbps scale
```

### 3. Sub-Second Convergence with BFD

Standard OSPF relies on periodic Hello/Dead intervals (10s / 40s). If a fiber link is degraded or intermediate switch crashes, OSPF takes **40 seconds** to declare the neighbor dead.
- **BFD (Bidirectional Forwarding Detection / RFC 5880):**
  - Runs hardware-accelerated keep-alives directly on interface ASICs at **50ms intervals**.
  - If 3 packets are dropped (150ms), BFD immediately alerts OSPF, triggering SPF recalculation and alternate path failover in **$<200$ milliseconds**.

## Common Interview Questions

**Q1: What happens to OSPF routing if an engineer forgets to adjust `auto-cost reference-bandwidth` on modern 10G/40G networks?**

If `auto-cost reference-bandwidth` is left at the default (100 Mbps), all interfaces $\ge 100\text{ Mbps}$ (FastEthernet, GigabitEthernet, 10-Gigabit, 100-Gigabit) receive a **cost of 1**. OSPF cannot distinguish between a slow 100 Mbps backup link and a 100 Gbps core optical backbone, causing ECMP to blindly send 50% of traffic across the 100 Mbps link, leading to immediate packet drops and link saturation.

**Q2: What is the purpose of the Discard Route automatically generated during OSPF route summarization?**

When an ABR or ASBR summarizes subnets (e.g., summarizing `10.1.1.0/24` through `10.1.3.0/24` into `10.1.0.0/16`), the router automatically installs a **Discard Route** (`10.1.0.0/16 -> Null0`) into its local routing table. This prevents **routing loops**: if a packet arrives for an unassigned subnet in the summary range (e.g. `10.1.99.1`), instead of bouncing back and forth between the ABR and the default gateway router, the packet hits the Null0 route and is dropped cleanly.

**Q3: How do OSPF SPF Throttling Timers prevent CPU starvation during network flapping?**

If a physical cable flaps up and down 10 times a second, recalculating Dijkstra's SPF tree on every flap would drive router CPUs to 100% and crash the network. OSPF SPF Throttling uses an exponential backoff formula with three timers:
1. `spf-delay`: Initial delay before running SPF (e.g. 50ms).
2. `spf-holdtime`: Minimum time between two consecutive SPF runs (e.g. 200ms).
3. `spf-max-wait`: Maximum delay before running SPF during continuous flapping (e.g. 5000ms).

**Q4: What is the difference between an OSPF Type 1 External (E1) and Type 2 External (E2) route?**

- **Type 2 External (E2 - Default):** The metric remains **fixed and constant** across the entire OSPF domain, showing only the external redistribution cost (e.g., Cost 20 everywhere).
- **Type 1 External (E1):** The metric is **cumulative**; it calculates the external redistribution cost PLUS the internal internal path cost to reach the ASBR. E1 is preferred when an organization has multiple exit ASBRs to ensure traffic exits via the closest border router.

**Q5: Can route summarization be performed on internal (non-ABR / non-ASBR) OSPF routers?**

No. Route summarization **cannot** be performed on internal routers within an Area. Because all routers within a single OSPF area must maintain an **identical Link State Database (LSDB)** to compute loop-free SPF trees, allowing an internal router to arbitrarily summarize or filter Type 1/2 LSAs would corrupt the graph topology and break Dijkstra's algorithm.
