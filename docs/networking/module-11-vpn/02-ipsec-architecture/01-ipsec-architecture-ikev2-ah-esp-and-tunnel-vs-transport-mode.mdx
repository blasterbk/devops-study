# Chapter 2 — IPsec Architecture: IKEv2, AH vs ESP & Tunnel vs Transport Modes

> **Goal:** Master Internet Protocol Security (IPsec, RFC 4301–4309), the legacy enterprise and cloud standard for Site-to-Site VPNs (AWS Site-to-Site VPN, Azure VPN Gateway, Cisco ASA). Understand the Internet Key Exchange protocol (IKEv1 vs IKEv2), Security Associations (SA), Security Policy Database (SPD), Authentication Header (AH) vs Encapsulating Security Payload (ESP), Tunnel vs Transport modes, and NAT-Traversal (NAT-T over UDP port 4500).
>
> By the end of this chapter, you will understand:
> 1. The two IPsec security protocols: Authentication Header (AH / IP Protocol `51`) vs Encapsulating Security Payload (ESP / IP Protocol `50`)
> 2. Tunnel Mode (site-to-site gateway encryption with a new outer IP header) vs Transport Mode (host-to-host payload encryption)
> 3. Internet Key Exchange v2 (IKEv2 / RFC 7296): `IKE_SA_INIT` and `IKE_AUTH` message exchanges
> 4. Security Associations (SAs), Security Parameter Index (SPI), and Security Policy Database (SPD)
> 5. NAT-Traversal (NAT-T / RFC 3948): encapsulating ESP packets inside UDP port 4500 to pass through PAT firewalls
> 6. CLI configuration and diagnostics using `strongSwan` (`ipsec status`, `swanctl`)

## Real-Life Analogy

Think of IPsec as **an armored diplomatic postal truck system between corporate branch offices**:

- **Transport Mode (Armored Safe Inside Your Own Car):**
  - You put a secure steel safe around your cargo, but you drive your own private car with your original license plates visible (**Host-to-Host; original IP header is preserved**).
- **Tunnel Mode (Armored Postal Carrier Truck):**
  - Your entire car (including original driver and license plates) is loaded inside a giant armored military transport truck with new official government license plates (**Gateway-to-Gateway; new outer IP header is added**). Observers on the highway cannot see who is inside.
- **ESP vs AH (Encryption vs Signature Only):**
  - **AH (Signature Only):** You seal the envelope with wax; anyone can hold it to the light and read the letter, but nobody can tamper with it (**Integrity only, Zero Encryption**).
  - **ESP (Complete Encryption & Integrity):** You shred the message into unbreakable ciphertext and lock it in the armored vault (**Confidentiality + Integrity**).

### 2. IKEv2 (Internet Key Exchange v2 / RFC 7296)

IKEv2 operates over **UDP Port 500** (or UDP 4500 for NAT-T) in two rapid round-trips (4 messages):
1. **`IKE_SA_INIT` (1st RTT):** Negotiates cryptographic algorithms (AES-GCM, DH Group 14/19), exchanges nonces, and completes Diffie-Hellman key exchange.
2. **`IKE_AUTH` (2nd RTT):** Authenticates peers using Pre-Shared Keys (PSK) or X.509 Certificates, verifies identities, and establishes the first **Child IPsec SA** for data traffic.

---

### 3. NAT-Traversal (NAT-T / RFC 3948)

Because ESP (IP Protocol 50) has no Layer 4 Port numbers, standard PAT routers cannot track or translate ESP connections. Furthermore, AH includes the IP header in its hash, so NAT's IP modification immediately corrupts AH checksums.
- **NAT-T Solution:** During IKE negotiation, endpoints detect intermediate NAT gateways. All ESP packets are encapsulated inside standard **UDP Port 4500** headers, allowing seamless traversal across NAT firewalls.

## Common Interview Questions

**Q1: Why is Authentication Header (AH) completely incompatible with Network Address Translation (NAT)?**

AH computes an integrity checksum over the entire packet, **including the outer IP header's Source and Destination IP addresses**. When the packet hits a NAT router, the router modifies the IP address (SNAT or DNAT). When the receiving endpoint verifies the AH hash against the modified IP header, the checksum fails, and the packet is discarded as tampered with.

**Q2: What is the difference between IPsec Tunnel Mode and Transport Mode?**

- **Transport Mode:** Encrypts only the Layer 4 payload while keeping the original IP header visible. Used for host-to-host end-to-end communication where both endpoints are the cryptographic endpoints.
- **Tunnel Mode:** Encrypts the **entire original IP packet** (including original IP headers) and encapsulates it inside a brand-new outer IP header. Used for Site-to-Site VPNs connecting two remote office networks across the public Internet.

**Q3: How does NAT-Traversal (NAT-T) detect whether NAT is present on the path?**

During the `IKE_SA_INIT` exchange, both endpoints compute a SHA-1 hash of the Source IP, Source Port, Destination IP, and Destination Port (`NAT_DETECTION_SOURCE_IP` and `NAT_DETECTION_DESTINATION_IP` payloads). If intermediate NAT modified the IP or port in transit, the calculated hash does not match the received hash, automatically triggering NAT-T fallback to **UDP port 4500**.

**Q4: What is Perfect Forward Secrecy (PFS) in IPsec?**

PFS ensures that if an attacker compromises the long-term private key or master IKE SA key in the future, they **cannot decrypt past recorded VPN sessions**. When PFS is enabled, the router executes a brand-new Diffie-Hellman key exchange for every individual Child SA rekey cycle, generating unique, ephemeral encryption keys that are discarded upon session completion.

**Q5: What is the Security Parameter Index (SPI) in an IPsec packet?**

The SPI is a 32-bit identifier in the ESP/AH header. When a router receives an encrypted IPsec packet, it uses the combination of the **Destination IP and SPI** to look up the matching **Security Association (SA)** in its local database to locate the correct decryption key and cryptographic algorithm.
