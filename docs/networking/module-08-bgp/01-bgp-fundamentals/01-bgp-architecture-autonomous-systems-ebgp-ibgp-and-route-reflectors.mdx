# Chapter 1 — BGP Fundamentals: Autonomous Systems, eBGP, iBGP & Route Reflectors

> **Goal:** Master the core architecture of Border Gateway Protocol (BGP-4, RFC 4271), the routing protocol that powers the global Internet. ## Real-Life Analogy

Think of BGP as **the international treaty and customs network connecting sovereign countries**:

- **Autonomous System (A Sovereign Country):**
  - Country A (Google, ASN 15169) and Country B (Cloudflare, ASN 13335) each have their own internal laws (**OSPF / IS-IS**).
- **External BGP (eBGP — International Border Ambassadors):**
  - Diplomats meet at international border crossings (**IXPs / Tier-1 Transit**). They exchange formal treaties: *"Country A will accept trade packets destined for `8.8.8.0/24`"*.
- **Internal BGP (iBGP — Federal Courier Service):**
  - Once the treaty enters Country A, internal couriers distribute the route to all domestic city halls.
- **Route Reflectors (Central Dispatch Hub):**
  - Instead of forcing all 1,000 city halls to maintain a direct telephone line to every other city hall ($N(N-1)/2$ full mesh), all city halls connect to 2 Central Dispatch Towers (**Route Reflectors**) that broadcast updates to everyone.

## Deep Technical Content

### 1. Autonomous System Numbers (ASN)

An AS is a collection of IP routing prefixes under a single administrative entity.
- **Public ASNs (Global Internet):** `1 – 64,495` (16-bit) and `131072 – 419999` (32-bit).
- **Private ASNs (Enterprise / Datacenter):** `64,512 – 65,534` (16-bit) and `4200000000 – 4294967294` (32-bit).

### 2. The 6-Stage BGP Finite State Machine (FSM)

```text
 ┌───────────────┬─────────────────────────────────────────────────────────────────────────────┐
 │ State         │ Description & Operation                                                     │
 │───────────────┼─────────────────────────────────────────────────────────────────────────────┤
 │ **1. Idle**   │ Router initializes resources and listens for TCP connection.                │
 │ **2. Connect**│ Initiates TCP 3-way handshake on port 179 with neighbor.                    │
 │ **3. Active** │ TCP handshake failed; router actively attempts to re-establish TCP socket.  │
 │ **4. OpenSent**│ TCP connected! Router transmits `BGP OPEN` message (ASN, BGP ID, Hold Time).│
 │ **5. OpenConfirm**│ Receives matching OPEN message from peer and transmits `KEEPALIVE`.     │
 │ **6. Established**│ Session fully active! Peers continuously exchange `UPDATE` routing msgs. │
 └───────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

### 3. eBGP vs iBGP Mechanics

```text
 ┌──────────────────────┬──────────────────────────────────────────┬──────────────────────────────────────────┐
 │ Feature              │ eBGP (External BGP)                      │ iBGP (Internal BGP)                      │
 │──────────────────────┼──────────────────────────────────────────┼──────────────────────────────────────────┤
 │ **Peering Location** │ Between different ASNs                   │ Within the same ASN                      │
 │ **Default IP TTL**   │ `TTL = 1` (Direct physical link required)│ `TTL = 255` (Multi-hop IGP routed)       │
 │ **AS-Path Action**   │ Prepends its own ASN to AS-Path          │ Does NOT modify AS-Path                  │
 │ **Next-Hop Action**  │ Changes Next-Hop to its own peering IP   │ Preserves external Next-Hop (needs self) │
 │ **Split-Horizon**    │ None                                     │ Never forward iBGP route to other iBGP   │
 └──────────────────────┴──────────────────────────────────────────┴──────────────────────────────────────────┘
```

---

### 4. Route Reflectors (RR) & Loop Prevention

To eliminate the $N(N-1)/2$ full-mesh requirement in large iBGP networks, **Route Reflectors** are permitted to forward iBGP routes to client peers. Loop prevention uses two mandatory non-transitive attributes:
1. **`ORIGINATOR_ID`:** The BGP Router-ID of the router that originally created the route. If an update returns with a router's own Originator ID, it is discarded.
2. **`CLUSTER_LIST`:** Sequence of Route Reflector Cluster IDs the route has traversed.

## Common Interview Questions

**Q1: Why does iBGP require an iBGP Split-Horizon rule, and why does that force a full-mesh or Route Reflector topology?**

In eBGP, loops are prevented because routers discard any update containing their own ASN in the AS-Path. However, within an AS, **iBGP does not append its own ASN** to the AS-Path. To prevent internal loops, iBGP enforces **Split Horizon: an iBGP router must never forward a route learned from an iBGP peer to any other iBGP peer**. This rule means routes can only travel 1 hop internally, forcing all iBGP routers to peer with every other iBGP router (Full Mesh: $N(N-1)/2$ sessions) or deploy **Route Reflectors**.

**Q2: What is the purpose of the `next-hop-self` configuration command in iBGP?**

When an edge router learns a route via eBGP from a transit provider, the route's Next-Hop IP is set to the external ISP IP (e.g. `203.0.113.1`). When the edge router reflects this route into iBGP, standard iBGP rules **preserve the external Next-Hop**. Internal routers cannot reach `203.0.113.1` (because external IPs are not in the internal IGP), causing the route to be marked unusable. `neighbor <peer> next-hop-self` forces the edge router to rewrite the Next-Hop to its own internal Loopback IP.

**Q3: What causes a BGP session to get stuck in the `Active` state?**

The `Active` state indicates the router is actively trying to initiate a TCP connection on port 179, but the TCP handshake is failing. Common causes:
1. An intermediate firewall or security group is blocking **TCP Port 179**.
2. An IP mismatch in the `neighbor <ip>` configuration (peering IP does not match the source interface).
3. The peer has no valid Layer 3 route back to the source IP.
4. eBGP Multihop is missing when peering across Loopback interfaces (`ebgp-multihop 2`).

**Q4: What is the difference between BGP Multihop and standard eBGP peering?**

By default, eBGP packets have an IP `TTL = 1`, enforcing that eBGP peers must be directly connected by a physical cable. If two eBGP routers peer using their **Loopback interfaces** for redundancy across dual physical cables, packets require 2 hops ($\text{TTL}=2$). Enabling `ebgp-multihop 2` allows eBGP packets to survive the extra hop without being dropped.

**Q5: What are BGP 4-Byte ASNs and how does BGP maintain backward compatibility with legacy 2-Byte peers?**

Standard ASNs were 16-bit integers ($1\dots 65535$). When ASNs neared exhaustion, RFC 4893 introduced 32-bit (4-byte) ASNs ($1\dots 4,294,967,295$). For backward compatibility with legacy 2-byte routers that cannot parse 32-bit ASNs, BGP uses a reserved placeholder ASN **`23456` (`AS_TRANS`)** in the legacy AS-Path while encoding the true 4-byte ASN in a new BGP attribute (`NEW_AS_PATH`).
